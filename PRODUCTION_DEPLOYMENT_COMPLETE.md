## UCM PRODUCTION SETUP (After Deployment)

### First Login to UCM

1. **Access**: https://store-frontend-prod-XXXX.onrender.com/admin-register
2. **Create admin account** (first registration)
3. **Login** at /admin-login
4. **Navigate to**: /admin/ucm (or Admin → UCM menu)

### Initialize UCM

1. **Discover Catalogs**: Click "Discover Catalogs" button
   - System queries 360Dialog for available catalogs
   - Shows list of catalogs on your account

2. **Select Primary Catalog**: Click "Select" on desired catalog
   - Marks this as the primary catalog
   - Other catalogs can be deleted (optional)

3. **Test with Dry-run**: Click "Sync All Products"
   - Mode is `dry_run` by default (safe)
   - Simulates sync without making changes
   - View results in Sync History

4. **Switch to Production**: After successful dry-run
   - Click Mode setting
   - Change from `dry_run` to `production`
   - Confirm "Activate Production Sync"

5. **Full Sync**: Click "Sync All Products" again
   - Real products synced to catalog
   - Monitor Sync History for status
   - Check backend logs for details

## IMPORTANT: 360DIALOG WEBHOOK CONFIGURATION

After deployment, you must configure webhook in 360Dialog:

1. Go to [360Dialog Hub](https://hub.360dialog.io)
2. Navigate to **Settings** → **Webhooks**
3. Set webhook URL to: `https://store-backend-prod-XXXX.onrender.com/api/v1/webhook/whatsapp`
4. Set webhook verify token to: Your generated `WHATSAPP_WEBHOOK_VERIFY_TOKEN`
5. Test webhook verification
6. Save configuration

**Without this, WhatsApp messages won't be received!**

---

## IMPORTANT: RAZORPAY WEBHOOK CONFIGURATION

After deployment, configure Razorpay webhook:

1. Go to [Razorpay Dashboard](https://dashboard.razorpay.com)
2. Navigate to **Settings** → **Webhooks**
3. Create new webhook:
   - URL: `https://store-backend-prod-XXXX.onrender.com/api/v1/webhook/razorpay`
   - Events: `payment.authorized`, `payment.failed`, `order.paid`
4. Copy generated webhook secret
5. Update backend env: `RAZORPAY_WEBHOOK_SECRET` = copied secret
6. Redeploy backend service

## DEBUGGING THE ADMIN REGISTRATION ISSUE

If registration still fails after deployment:

### Check These in Order

1. **Verify FRONTEND_URL in backend**
   - Render dashboard → store-backend → Environment
   - Find `FRONTEND_URL`
   - Should be: `https://store-frontend-prod-XXXX.onrender.com`

2. **Verify NEXT_PUBLIC_API_URL in frontend**
   - Render dashboard → store-frontend → Environment
   - Find `NEXT_PUBLIC_API_URL`
   - Should be: `https://store-backend-prod-XXXX.onrender.com/api/v1`

3. **Check backend logs**
   - Render dashboard → store-backend → Logs
   - Look for error messages during registration attempt
   - Common errors:
     - "Cannot connect to MongoDB" → Wrong `MONGODB_URI`
     - "Invalid JWT" → Wrong `JWT_SECRET`
     - 400/500 errors → Check actual error message in logs

4. **Browser console errors**
   - Frontend: F12 → Console tab
   - Look for CORS errors or network errors
   - Check exact error message

5. **Test endpoint directly**
   ```bash
   curl -X POST https://store-backend-prod-XXXX.onrender.com/api/v1/auth/admin/register \
     -H "Content-Type: application/json" \
     -H "Origin: https://store-frontend-prod-XXXX.onrender.com" \
     -d '{
       "name": "Test",
       "email": "test@example.com",
       "password": "TestPass123!",
       "phone": "+1234567890"
     }'
   ```
   - Should return success or specific error
