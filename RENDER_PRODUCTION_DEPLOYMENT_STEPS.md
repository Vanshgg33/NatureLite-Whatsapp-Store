**Target**: Deploy `production` branch to Render  
**Services**: store-backend + store-frontend  
**Configuration File**: `render.yaml`  
**Date**: April 24, 2026

```bash

# Should show: * production (branch is checked out)

# Verify latest commits from feat/ucm-catalog-sync are present
```

```bash
# Verify render.yaml exists and is configured for production
git show production:render.yaml | head -20

# Verify backend configuration
git show production:backend/src/config/configuration.ts | head -30

git show production:frontend/src/lib/api.ts | head -20
```

2. Sign in with your account (create if needed)

2. Click on service to expand environment variables section
3. For each variable marked `sync: false` in render.yaml, enter the value:

#### Backend Environment Variables Input Form

**Critical Variables** (⚠️ enter exactly):

| Variable | Value | From |

| `FRONTEND_URL` | `https://store-frontend-prod-XXXX.onrender.com` | Render (you'll get this after frontend is deployed, start with frontend domain) |
| `MONGODB_URI` | `mongodb+srv://user:pass@cluster.mongodb.net/store-production?...` | MongoDB Atlas connection string |
| `JWT_SECRET` | `uSK1Ij0Vr1Hp81qrXhD7cf8fmBEIKT4gzJQ4ahZfReY=` | Use provided value |
| `WHATSAPP_D360_API_KEY` | Your production 360Dialog API key | 360Dialog Hub |
| `WHATSAPP_WEBHOOK_VERIFY_TOKEN` | Generated token (e.g., output of `openssl rand -base64 24`) | Self-generated |

**Cloudinary** (⚠️ enter exactly):

| Variable | Value | From |
|----------|-------|------|
| `CLOUDINARY_CLOUD_NAME` | Cloud name from Cloudinary | Cloudinary dashboard |
| `CLOUDINARY_API_KEY` | API key from Cloudinary | Cloudinary dashboard |
| `CLOUDINARY_API_SECRET` | API secret from Cloudinary | Cloudinary dashboard ⚠️ keep secret |

**Razorpay** (⚠️ enter exactly):

| Variable | Value | From |
|----------|-------|------|
| `RAZORPAY_KEY_ID` | Key ID from Razorpay | Razorpay dashboard |
| `RAZORPAY_KEY_SECRET` | Key secret from Razorpay | Razorpay dashboard ⚠️ keep secret |
| `RAZORPAY_WEBHOOK_SECRET` | Webhook secret (set after webhook config) | Razorpay webhook settings |

## Phase 3: Initial Deployment

### 3.1 Review Deployment Settings

Before deployment, verify:

- [ ] Branch: `production`
- [ ] Both services listed: `store-backend` and `store-frontend`
- [ ] Environment variables entered for backend (at minimum: `MONGODB_URI`, `JWT_SECRET`, `WHATSAPP_D360_API_KEY`)
- [ ] Health check path: `/api/v1/health`

### 3.2 Disable Auto-Deploy (Safety First)

⚠️ **Important**: For first production deployment, disable auto-deploy:

1. In service settings for `store-backend`:
   - Find "Auto-Deploy" toggle
   - Disable it (turn OFF)
   
2. In service settings for `store-frontend`:
   - Find "Auto-Deploy" toggle
   - Disable it (turn OFF)

This prevents accidental redeployments before testing.

### 3.3 Trigger Initial Deployment

1. Click **"Deploy"** or **"Create"** button
2. You'll see deployment progress screen
3. Wait for both services to build and start

**Expected build time**: 5-10 minutes for both services

### 3.4 Monitor Deployment Logs

1. Click on `store-backend` service
2. Navigate to **"Logs"** tab
3. Watch for:
   - Build success: "npm run build completed"
   - Server startup: "Nest initialized" or similar
   - Health check passing: "GET /api/v1/health 200 OK"

If you see errors:
- Check MongoDB URI (connection refused = wrong credentials)
- Check JWT_SECRET (encoding issues = invalid characters)
- Check API keys (missing env vars = 400 errors)

## Phase 4: Post-Deployment Configuration

### 4.1 Get Auto-Generated URLs

1. In Render dashboard, click on `store-backend` service
2. Note the URL: `https://store-backend-prod-XXXX.onrender.com`
3. In Render dashboard, click on `store-frontend` service
4. Note the URL: `https://store-frontend-prod-XXXX.onrender.com`

### 4.2 Update Frontend Environment Variables

Now that backend is deployed, update frontend's API URL:

1. In `store-frontend` service settings
2. Find "Environment" section
3. Update `NEXT_PUBLIC_API_URL`:
   - Old: `http://localhost:7001/api/v1` or placeholder
   - New: `https://store-backend-prod-XXXX.onrender.com/api/v1`
4. Update `NEXT_PUBLIC_SITE_URL`:
   - New: `https://store-frontend-prod-XXXX.onrender.com`
5. Click **"Save"** or **"Update"**
6. Trigger redeploy of frontend service

### 4.3 Update Backend FRONTEND_URL

1. In `store-backend` service settings
2. Find "Environment" section
3. Update `FRONTEND_URL`:
   - Old: previous sandbox URL or placeholder
   - New: `https://store-frontend-prod-XXXX.onrender.com`
4. Click **"Save"** or **"Update"**
5. Service should auto-restart with new FRONTEND_URL

### 4.4 Configure 360Dialog Webhook

1. Go to [360Dialog Hub](https://hub.360dialog.io)
2. Login to your production account
3. Navigate to **"Settings"** → **"Webhooks"**
4. Create/update webhook:
   - **URL**: `https://store-backend-prod-XXXX.onrender.com/api/v1/webhook/whatsapp`
   - **Verify Token**: Use the value you set for `WHATSAPP_WEBHOOK_VERIFY_TOKEN`
   - Click **"Save"**
5. Test webhook (360Dialog should verify the endpoint)

### 4.5 Configure Razorpay Webhook

1. Go to [Razorpay Dashboard](https://dashboard.razorpay.com)
2. Navigate to **"Settings"** → **"Webhooks"**
3. Create new webhook:
   - **URL**: `https://store-backend-prod-XXXX.onrender.com/api/v1/webhook/razorpay`
   - **Events to subscribe**: `payment.authorized`, `payment.failed`, `order.paid`
   - Click **"Create"**
4. Copy the generated **Webhook Secret**
5. Update backend environment variable `RAZORPAY_WEBHOOK_SECRET` with this value
6. Save and redeploy backend service

## Phase 8: Troubleshooting

### Issue: Backend service crashes immediately

**Symptoms**: Status shows "crashed" or "exited"

**Check**:
1. Logs: Render → service → Logs
2. Look for errors like:
   - "ECONNREFUSED" → MongoDB connection issue
   - "Cannot find module" → Build issue
   - "Validation failed" → Environment variable issue

**Fix**:
1. Verify `MONGODB_URI` is correct
2. Verify all required env vars are set
3. Check IP whitelist in MongoDB Atlas

### Issue: Admin registration fails with "Registration failed. Please try again."

**Symptoms**: Frontend shows error message, no backend logs

**Check**:
1. Browser console (F12 → Console) for error details
2. Backend logs for actual error
3. CORS configuration

**Fix**:
1. Verify `FRONTEND_URL` is set to your frontend domain
2. Verify backend can reach MongoDB
3. Check that email isn't already registered

### Issue: WhatsApp webhook not working

**Symptoms**: Messages not being received

**Check**:
1. 360Dialog Hub → Webhooks → Test webhook
2. Backend logs for webhook errors
3. Verify webhook URL is exactly: `https://store-backend-prod-XXXX.onrender.com/api/v1/webhook/whatsapp`

**Fix**:
1. Verify `WHATSAPP_WEBHOOK_VERIFY_TOKEN` matches in both places
2. Check that backend service is running (health check)
3. Re-verify webhook in 360Dialog Hub

### Issue: Frontend showing "Cannot connect to API"

**Symptoms**: Frontend can't reach backend

**Check**:
1. Verify `NEXT_PUBLIC_API_URL` is correct
2. Backend is running (health check passes)
3. CORS is enabled in backend

**Fix**:
1. Update `NEXT_PUBLIC_API_URL` to correct backend URL
2. Redeploy frontend service
3. Clear browser cache (Ctrl+Shift+Delete)

## Rollback Procedure

If production deployment has critical issues:

### Immediate Rollback

1. In Render dashboard, find `store-backend` service
2. Click **"Deployments"** tab
3. Find the last working deployment (before current)
4. Click "Re-deploy"
5. Wait for rollback to complete
6. Verify health check: `curl https://...onrender.com/api/v1/health`

### Investigation

After rollback:
1. Review deployment logs of failed version
2. Check what changed (git diff)
3. Fix issues in `production` branch
4. Push fix to git
5. Deploy again
